CheckMyWeb 사용 설명서

CheckMyWeb(체크마이웹)은 내 웹사이트의 HTTPS, 보안 헤더, 노출 파일, 메일 도메인 설정을 외부에서 점검하고, 감지한 서버 종류에 맞는 조치 방법을 알려 주는 명령줄 프로그램입니다.

1. 시작하기

CheckMyWeb은 Python 3.11 이상에서 동작하며 추가 패키지가 필요 없습니다. 웹사이트 서버에는 아무것도 설치하지 않습니다.

  1. python.org에서 Python을 내려받아 설치합니다. Windows 설치 화면에서는 py launcher와 Add python.exe to PATH를 함께 선택하면 편리합니다.
  2. 명령 프롬프트에서 py --version을 실행해 Python 3.11 이상이 표시되는지 확인합니다.
  3. 배포 ZIP(CheckMyWeb-@VERSION@.zip)을 원하는 폴더에 풉니다. 설치 과정은 없습니다.
파일설명
checkmyweb.pyz프로그램 본체 (Python으로 실행)
checkmyweb.cmdWindows 실행 도우미 (py 또는 python으로 본체 실행)
README.txt간단한 안내
manual.html이 사용 설명서
LICENSE.txt사용권 계약

2. 첫 점검

  1. 압축을 푼 폴더를 탐색기로 열고, 주소창에 cmd를 입력한 뒤 Enter를 눌러 명령 프롬프트를 엽니다.
  2. 점검할 도메인을 붙여 실행합니다. 
    checkmyweb.cmd example.com
  3. 점검이 끝나면 화면에 결과가 요약되고, reports 폴더에 HTML·JSON 보고서가 저장됩니다.

PowerShell에서는 .\checkmyweb.cmd example.com으로 실행합니다. macOS·Linux에서는 python3 checkmyweb.pyz example.com으로 실행하며, 이 환경은 아직 직접 검증하지 않았습니다.

3. 보고서 읽기

reports 폴더의 HTML 파일을 브라우저로 열면 등급, 위험도별 개수, 서버 환경, 우선 조치 항목이 맨 위에 나오고 그 아래에 점검 영역별 결과가 이어집니다. 위험도 버튼을 누르면 원하는 위험도의 항목만 볼 수 있습니다.

위험도의미감점
심각바로 악용될 수 있는 노출 (예: .git·.env 공개, 만료된 인증서)30
높음중요한 방어 장치가 없음 (예: HSTS 없음, HTTPS로 전환되지 않는 로그인 페이지)15
보통권장 방어 장치가 없음 (예: CSP 없음, 세션 쿠키 속성 미흡)5
낮음하드닝 권장 사항 (예: 버전 정보 노출, TRACE 허용)1
정보참고 사항0
양호잘 설정된 항목0

100점에서 감점하며 한 점검 영역의 감점은 최대 40점입니다. 90점 이상 A, 80점 이상 B, 65점 이상 C, 50점 이상 D, 그 아래는 F이고, 심각 항목이 있으면 최고 D입니다. 점수는 우선순위를 정하기 위한 참고치이며, 발견되지 않은 문제가 없다는 뜻은 아닙니다.

3.1 조치 방법

각 항목의 조치 방법에는 감지된 서버의 설정 예시가 나옵니다. 서버를 알 수 없으면 Apache와 nginx 예시를 함께 보여 주고, CDN 뒤의 사이트는 CDN 콘솔에서 바꿀 설정을 먼저 안내합니다.

조치 예시는 일반적인 설정 예입니다. 아래 순서로 적용하세요.

  1. 바꾸기 전에 현재 설정 파일을 백업합니다.
  2. 설정을 바꾼 뒤 웹 서버 설정 검사(apachectl -t, nginx -t)를 거쳐 재시작합니다.
  3. 사이트가 정상으로 열리는지 확인하고 다시 점검합니다.

HSTS와 CSP는 잘못 설정하면 사이트 접속이나 기능에 영향을 줄 수 있습니다. HSTS는 짧은 max-age로, CSP는 Content-Security-Policy-Report-Only 헤더로 먼저 시험한 뒤 적용하세요.

4. 소유 확인

.env, .git, 백업 파일, 관리자 페이지 같은 민감 파일 노출 점검과 포트 점검은 사이트의 약점을 그대로 드러내므로, 도메인 소유를 확인한 뒤에만 실행합니다. 확인 전에는 두 점검이 "건너뜀"으로 표시되고 나머지 점검은 그대로 진행됩니다.

  1. 소유 확인 안내를 엽니다. 이 컴퓨터 전용 토큰과 두 가지 확인 방법이 표시됩니다. 
    checkmyweb.cmd verify example.com
  2. 둘 중 한 가지 방법으로 토큰을 등록합니다.
    • DNS TXT 레코드 (권장): 도메인 관리 화면에서 이름 _checkmyweb.example.com, 값 checkmyweb-verify=…인 TXT 레코드를 추가합니다. 등록 도메인과 모든 서브도메인에 적용됩니다.
    • 확인 파일: https://example.com/.well-known/checkmyweb-verify.txt에 토큰을 담은 파일을 올립니다. 해당 주소(호스트·포트)에만 적용되며, DNS가 없는 사내 서버에도 쓸 수 있습니다.
  3. verify를 다시 실행해 "확인됨"이 나오면 점검을 다시 합니다.

DNS 변경은 반영까지 몇 분에서 몇 시간이 걸릴 수 있습니다. 토큰은 컴퓨터마다 다르므로 여러 컴퓨터에서 점검한다면 각 컴퓨터의 토큰을 TXT 레코드로 모두 추가하세요(같은 이름에 여러 값을 둘 수 있습니다). 내 컴퓨터(127.0.0.1 등)에서 실행 중인 개발 서버는 확인 없이 점검합니다.

소유 확인은 도메인을 관리하고 있다는 것을 보여 줄 뿐, 서버를 점검할 권한까지 증명하지는 않습니다. 서버를 호스팅·클라우드 사업자가 운영한다면 포트 점검 전에 해당 사업자의 이용 정책을 확인하세요.

5. 여러 사이트 점검

대상을 여러 개 적거나 목록 파일을 지정하면 차례대로 점검하고 요약 보고서를 만듭니다. 한 번에 최대 50개까지 점검할 수 있습니다.

checkmyweb.cmd example.com shop.example.com
checkmyweb.cmd -f sites.txt

목록 파일은 한 줄에 대상 하나를 적고, # 뒤는 주석으로 무시합니다.

# 운영 중인 사이트
example.com
shop.example.com
https://admin.example.com:8443/   # 관리 페이지

결과는 reports\batch-날짜-시각 폴더에 대상별 HTML·JSON과 요약 페이지 index.html, summary.json으로 저장됩니다. 화면에는 대상별 등급과 위험도 개수 표가 나오며, --details를 붙이면 항목별 결과도 모두 출력합니다.

6. 포트·경로·사내 인증서

  • 포트와 경로: https://example.com:8443/app/처럼 적으면 해당 포트의 TLS를 점검하고, 노출 파일은 /app/ 아래를 기준으로 찾습니다. 서버 전체에 해당하는 항목(security.txt, 서버 상태 페이지 등)은 사이트 루트에서 확인합니다.
  • HTTP 리다이렉트 포트: HTTPS를 비표준 포트로 운영하면 짝이 되는 HTTP 포트를 알 수 없으므로, --http-port 8080처럼 지정해야 리다이렉트를 점검합니다.
  • 사내 CA 인증서: 사내 인증기관이 발급한 인증서를 쓰는 서버는 --ca-file 사내CA.pem으로 CA 인증서를 지정하면 인증서 오류 없이 점검합니다.
  • IP 주소·사내 도메인: https://10.0.0.5/나 intranet.local도 점검할 수 있으며, 공인 DNS가 없으므로 DNS·이메일 점검은 건너뜁니다.

9. 정기 점검과 종료 코드

종료 코드는 0(기준 미만), 1(--fail-on 이상의 항목 발견), 2(대상의 주소를 찾을 수 없음)입니다. Windows 작업 스케줄러에 등록하면 인증서 만료나 설정 변경을 정기적으로 확인할 수 있습니다.

schtasks /Create /SC WEEKLY /D MON /ST 09:00 /TN CheckMyWeb ^
  /TR "\"C:\Tools\CheckMyWeb\checkmyweb.cmd\" -f C:\Tools\CheckMyWeb\sites.txt -o C:\Tools\CheckMyWeb\reports"

Linux·macOS에서는 cron에 python3 /opt/checkmyweb/checkmyweb.pyz -f sites.txt -o reports를 등록합니다.

10. 자주 묻는 질문

점검 정보가 외부로 전송되나요?

점검 요청은 점검 대상 사이트(리다이렉트로 이어지는 주소 포함)로 보냅니다. DNS 레코드 조회에는 Cloudflare와 Google의 공개 DNS-over-HTTPS 서비스를 사용하므로, 점검하는 도메인 이름이 이 서비스에 전달됩니다. WooklyDev 서버로는 어떤 정보도 보내지 않으며, 보고서는 내 컴퓨터에만 저장됩니다.

점검 대상 서버에는 어떻게 기록되나요?

요청의 User-Agent에 checkmyweb/버전과 제품 페이지 주소가 표시되어 서버 로그에 남습니다. 요청 수가 적고 요청 사이에 간격을 두지만, 대상 서버의 보안 장비(웹 방화벽 등)가 경보를 내거나 내 IP를 차단할 수 있습니다. 다른 사람이 관리하는 서버라면 점검 전에 관리자에게 알리세요.

결과가 실제 설정과 다르게 나옵니다.

CheckMyWeb은 홈페이지와 정해진 경로만 확인하며 로그인 뒤의 페이지는 보지 않습니다. CDN이나 방화벽이 요청을 막으면 일부 항목을 확인하지 못할 수 있습니다. 보고서의 "근거"에 실제 응답이 적혀 있으니 함께 확인하세요.

Windows에서 "Python 3.11 or later is required"가 표시됩니다.

Python이 설치되지 않았거나 PATH에 없습니다. 1장을 참고해 설치한 뒤 명령 프롬프트를 새로 여세요.

보고서는 어떻게 관리해야 하나요?

보고서에는 사이트의 약점이 담겨 있습니다. 외부에 공유하지 말고, 조치를 마친 뒤에는 삭제하거나 안전한 곳에 보관하세요.

11. 사용 시 유의사항

  • 점검 권한: 본인 소유이거나 소유자에게서 점검 권한을 받은 사이트·도메인·서버에만 사용하세요. 점검 대상의 선택과 권한 확인, 관련 법령(정보통신망 이용촉진 및 정보보호 등에 관한 법률 등)과 호스팅·CDN 서비스 약관의 준수는 사용자의 책임입니다.
  • 점검 결과의 한계: 공개된 응답과 DNS 정보만으로 판단하므로 실제와 다른 판정이 있을 수 있습니다. 결과는 문제가 없음을 보증하지 않으며, 전문 보안 진단이나 모의 해킹, 법령·인증 기준 충족 여부의 판단을 대신하지 않습니다.
  • 조치 예시의 적용: 조치 예시는 일반적인 설정 예입니다. 적용하기 전에 백업하고 내 환경에서 검토·시험하세요. 적용 여부와 그 결과는 사용자의 책임입니다.
  • 외부 서비스: DNS 조회에 쓰는 Cloudflare와 Google의 DNS-over-HTTPS 서비스에는 각 사업자의 정책이 적용됩니다.
  • 상표: 이 설명서와 프로그램에 나오는 제품명과 상표는 각 소유자의 것이며 식별 목적으로만 사용합니다. WooklyDev는 해당 회사와 제휴하거나 보증을 받지 않았습니다.
  • 보증과 책임: 프로그램은 "있는 그대로" 제공되며 어떤 보증도 하지 않습니다. 관련 법령이 허용하는 범위에서 WooklyDev는 프로그램의 사용, 점검 결과, 조치 예시의 적용으로 생긴 손해에 책임지지 않습니다. 정확한 조건은 LICENSE.txt를 따릅니다.
